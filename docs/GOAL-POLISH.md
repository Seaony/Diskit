# Kayoi 打磨与扩展目标

先读 AGENTS.md、PLAN.md、docs/ACCEPTANCE.md，再读 App/ 下全部文件和 Packages/*/Sources。
用户已批准本文件的范围；本文件和 PLAN.md 冲突时以本文件为准（PLAN §1 里「其它网盘不做」改为按本文件 B 部分做）。

现状问题：功能能跑，但界面和交互很粗糙，像开发者自用工具。目标是做到可以给普通 Mac 用户用的成品水平。
参考标准：macOS 自带 App（系统设置、Finder「连接服务器」、隔空投送面板）和 SideMount 的完成度。

## 硬约束

- 不用液态玻璃：面板、窗口、弹层都用不透明背景；按钮用实色填充加细边框（见 AGENTS.md），保留深浅色适配。
- 只用系统框架。新增第三方依赖必须先停下问用户。不手写密码学原语，HMAC、SHA 用 CryptoKit。
- OpenList / AList 是 AGPL，只能参考接口行为，不能复制代码；rclone 是 MIT，可以参考，但要在 docs/THIRD_PARTY_NOTICES.md 注明出处。
- 不删除已有功能，不悄悄降级行为。拿不准就保留原行为，写进报告。
- 所有新文案进 Localizable.xcstrings，中文和英文都要有，复数用 String Catalog 的 plural 变体。
- 代码注释用简短中文。每完成一个小节做一次小提交，提交信息一句中文。
- 阶段一仍然没有 FSKit：SMB 以外的类型（以及 B1 里能走系统挂载的类型以外的）仍然只做「测试连接」加 kayoi-dev，不要假装能挂载。

## A. 界面、交互、文案打磨（先做完 A 再做 B）

### A1 菜单栏面板（App/PanelView.swift、KayoiApp.swift）

1. 面板高度现在用 `contentHeight` 手算（每行 60、空状态 210、只给 SMB 的已发现分组加了 32），错误提示和分组标题没算进去，会被裁切。改成按内容自适应，最高 560pt，超出才滚动（PLAN §5）。
2. 「已发现」4 种设备各写了一份几乎一样的 HStack，图标样式也不统一（有的有彩色底块，有的没有）。合成一个行组件：类型图标 28pt 彩色方块、标题、副标题、「添加」按钮。已保存行和已发现行视觉一致，但要能一眼区分两者。
3. 已保存行的图标在 `row()` 里用三元表达式内联写死，和 `ConnectionKind.symbol` 不一致：阿里云盘和夸克都显示成 `icloud`。统一走 `symbol`，并让每种类型有能区分的图标。
4. 顶部胶囊在 0 个挂载时也显示「0 个已挂载」，阶段一非 SMB 类型永远是 0。改为没有挂载时不显示，或者显示更有用的信息（比如有连接出错时显示「1 个需要处理」）。英文复数要正确。
5. 行副标题出错时只显示一行，被截断，悬停提示也只有截断前的文字。出错时提供查看完整原因和复制的方式（悬停全文 + 右键「复制错误信息」）。连接中要在按钮或图标上显示进度，不能只把按钮变灰。
6. 主按钮：测试成功（.tested）后按钮仍然写「测试连接」，状态没有反馈。按状态区分文案和样式；成功、失败的结果要在行上停留可见。
7. 右键菜单补上：已挂载时的「推出」、「复制路径」；网盘行「重新登录」；所有行「上移 / 下移」（给不方便拖动、用键盘的人）。拖动排序要有插入位置指示，拖动时行要有抬起的样子。
8. 删除确认框要写出具体名称（「删除“我的 Pixel”？」），按类型说明后果（SMB 会先推出；网盘会删掉登录信息；本机文件不受影响）。
9. 发现出错（本地网络权限被拒）现在只显示一行灰字。改成带操作的提示条：说明原因，按钮打开「系统设置 › 隐私与安全性 › 本地网络」。
10. 空状态：PLAN F9 要求插图 + 「添加位置」按钮。现在只有文字，按钮在列表外，而且按钮外面套了 `.frame(maxWidth:)`，按钮本身并没有撑满。同时补上「插上手机、打开无线调试会自动出现在这里」这类引导。
11. 无线调试：同一台手机的「配对服务」和「连接服务」会各显示一行，名字是 `adb-XXXX` 这种服务名，还拼了「（Wi-Fi）」。合并成一台设备一行，尽量显示友好的名称；已经保存的手机不要再出现在「已发现」里。先核实 `discoveredWiFi` 的过滤条件（拿 guid 和 device.name 比）对配对服务是否失效。
12. 底部栏：版本号前加 App 名；「帮助」现在打开打包进去的 README.md，那是给开发者看的构建说明。改成面向用户的帮助内容（应用内帮助页面，或者一份新的用户帮助文档），讲清每种类型的准备步骤。「退出」前如果有本 App 挂载的卷，说明哪些会被推出（SMB 不受影响）。
13. 键盘：⌘N 添加、⌘, 设置、⌘Q 退出；上下方向键选择行，回车触发主按钮。VoiceOver 标签要完整。
14. 菜单栏图标上 4pt 的小圆点要核对：深浅色菜单栏、模板图片渲染下都看得见，位置对齐。
15. 全局 alert「操作失败」只有通用标题。改成写明是什么操作失败（「推出“xx”失败」），能给下一步操作的给按钮。

### A2 添加 / 编辑窗口（App/ConnectionEditor.swift、QuarkLoginView.swift）

1. 窗口标题固定写「添加或编辑位置」，改成按场景显示。Window 场景的 defaultSize 是 500 高，视图写死 620 / 500，两步切换时高度会跳，统一处理。
2. 选类型那一步：5 张卡片排 3 列，最后一行不齐；选中后还得再点「下一步」。支持双击卡片直接进入下一步。卡片标题用了 `kind == .androidUSB ? ... : kind == .quark ? ...` 的临时写法，改成正规的属性。说明文字 `"USB / Wi-Fi"` 没有本地化。B 部分会加很多类型，这一步要改成分组（设备 / 局域网 / 网盘 / 对象存储）加搜索，网盘类型显示「官方」或「实验性」标记。
3. 表头大图标用的是 `kind.iconColor`，面板行用的是用户选的 `connection.tint`，用户选的颜色在编辑窗口里看不到。统一为用户选的颜色。颜色选择改成色块，不用文字下拉框，颜色多给几种。
4. 「打开 App 时自动挂载」「挂载后自动在 Finder 打开」对所有类型都显示，但阶段一只有 SMB（和 B1 的系统挂载类型）能挂载。别的类型隐藏这两项，或者禁用并说明原因。
5. 校验：现在点了保存才统一报「请填写名称、主机、用户名和共享名」。改成逐个字段即时提示，必填项没填时「测试并保存」不能点；新建时名称按类型或设备名自动预填。
6. 测试中「取消」按钮被禁用，USB 授权最长要等 60 秒，OAuth 和扫码也没法中途放弃。必须能取消，取消后状态恢复干净。进度文案按实际阶段显示（「正在配对…」「等待手机授权…」「等待浏览器授权…」），不要一律写「正在测试连接…」。
7. 说明文字现在全堆在表单最底部。改成放在相关字段旁边，或做成可展开的「准备步骤」（安卓：开发者选项 → USB 调试；无线调试的配对步骤；Windows：开启文件共享、微软账户填邮箱）。「需配置开放平台 client_id 和回调地址」是开发者术语，普通用户界面不显示，只在确实没配置时给出能看懂的错误。
8. 设备选择：没发现设备时，下拉框里只有「请选择」。改成空状态说明加排查步骤；设备插入后自动选中。
9. 无线配对码现在是 SecureField。改成明文的 6 位数字输入，只允许数字，输满自动开始配对，配对码错误时可以直接重输。
10. SMB：主机框加示例占位文字（如「192.168.1.10 或 DESKTOP-PC」）；「列出共享」得到结果后，用选择列表直接替换共享名输入框，不要上下各出现一份；支持访客登录；密码框可以显示密码。
11. 网盘：显示当前登录的账号和头像昵称（如果能拿到），提供「切换账号」。夸克登录弹层：网页区域跟随窗口大小，「手动粘贴 Cookie」改成「其他登录方式」，并解释这是什么、怎么拿。
12. 出错信息：红字之外，给出能操作的下一步（重试、打开系统设置、重新登录、复制详细信息）。

### A3 设置窗口（App/SettingsView.swift）

1. `AppModel.clearCache()` 会推出全部已挂载的卷，SMB 也会被推出，但 SMB 根本不用这块缓存。这是 bug：只推出用到缓存的卷，阶段一没有这类卷时不推出任何东西。阶段一缓存基本是空的，文案要如实说明。
2. ADB 指纹加「复制」按钮，并说明用途；「重新生成密钥」的确认框说明后果。
3. 开机启动出错时，报错放在开关旁边，不要放在表单最底部。
4. 新增「关于」：版本、致谢与第三方许可证（docs/THIRD_PARTY_NOTICES.md 已经打包了，界面里看不到）。
5. 新增通知设置：PLAN F19 的三类通知分别能开关。通知权限不要在第一次出错时才突然弹出，改到合适的时机说明后再请求。

### A4 文案和术语（全局）

1. 统一术语：「位置 / 连接 / 共享」现在混用（添加位置、我的位置、删除连接、编辑位置……）。定一套写进 docs/COPY.md，然后全局替换。
2. 去掉开发者术语：「此类型将在后续里程碑提供」、各种 client_id、Cookie 字段名等不出现在普通界面上。
3. 错误码：「系统操作失败（%d）」「远端操作失败（%d）」直接把数字给用户看。常见 POSIX / NetFS / HTTP 错误要映射成人话，原始码放进「详细信息」。`RemoteError.unauthorized` 固定写「请在手机上点允许 USB 调试」，网盘和相机报这个错时会误导人，按类型区分文案。
4. 全部中英文案逐条审一遍：语气一致、标点统一（中文全角，英文用 Title Case / Sentence case 按 macOS HIG）、没有直译腔。

### A5 对照 PLAN 逐条核实

把 F1–F19 和 §5 的 UI 规格逐条和现在的实现对照，不符合的修好。重点核实：F6 删除时清理钥匙串和缓存、F8 退出行为、F19 设备意外断开的通知是否真的实现了。结果写进报告。

## B. 新增位置类型（A 全部完成后再开始；按 B1 → B5 的顺序，一个做完、测完再做下一个）

每个新类型都要：独立的 Package 或放进合适的已有包；实现 RemoteFileProvider；正确声明 capabilities；错误映射到 POSIX；接入添加窗口和面板；kayoi-dev 能用；用假实现写单元测试（分页、鉴权刷新、错误映射、上传分片边界）；README 和 ACCEPTANCE 加一节，没有真实账号的项目标「待用户验收」，不能写通过。
需要开发者凭据的（client_id 等），照阿里云盘的做法：放 Config/Secrets.xcconfig，同时更新 Secrets.example.xcconfig，没配置时给出清楚的提示。

### B1 系统原生挂载（阶段一就能进 Finder，和 SMB 走同一套 NetFS 流程）

- 把「Windows 共享」改名为「SMB 共享（Windows / Mac / NAS）」，旧配置照常能用。
- WebDAV / WebDAV over HTTPS：覆盖坚果云、Nextcloud、ownCloud、群晖 / 威联通 NAS，以及 OpenList / AList 自己提供的 WebDAV（等于间接支持它们能接的所有网盘）。坚果云这类常见服务给预设（地址模板、「应用密码」获取说明）。
- NFS。
- 先在本机实测 `NetFSMountURLAsync` 对 http/https/nfs 的实际支持情况，写进报告，以实测为准。

### B2 对象存储（官方 API，一套 S3 兼容实现覆盖）

AWS S3、Cloudflare R2、阿里云 OSS、腾讯云 COS、七牛 Kodo、MinIO、Backblaze B2。SigV4 签名用 CryptoKit 实现；分片上传；不同服务的 endpoint 和 region 做预设。

### B3 官方开放平台网盘（OAuth，需要用户去申请 client_id）

百度网盘开放平台、115 开放平台、123 云盘开放平台、OneDrive（Microsoft Graph）、Google Drive、Dropbox。限流、令牌刷新、回收站语义、同名冲突规则都参照阿里云盘（PLAN §6.5）的做法，各自查官方文档确认。百度网盘非会员限速、下载要带指定 UA 这类限制，要在界面上如实说明。

### B4 非官方网页接口（实验性，和夸克同等对待：标注「可能随时失效」，同名上传报错不覆盖）

UC 网盘（和夸克同源，优先复用 Quark 包）、天翼云盘（个人 / 家庭）、移动云盘、迅雷云盘、PikPak、蓝奏云（以只读为主）。

### B5 设备扩展

GR IV 那套 ImageCaptureCore 读取泛化成「相机（USB）」，支持系统能识别的 PTP / MTP 相机（富士、索尼、佳能、尼康等）。GR IV 特有的逻辑保留。

### 不做，写进报告说明原因

iPhone / iPad、安卓 MTP（PLAN 非目标）；SFTP（需要 libssh2 之类的第三方依赖，等用户批准）；MEGA（端到端加密，要额外的密码学实现）；FTP（老协议，价值低，可以写成建议）。
