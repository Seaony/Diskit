# Kayoi 0.2 深度完善与验收规范

> 写给实现者。本文件是 Kayoi 下一轮工作的唯一任务清单和验收标准：把现在「类型很多、能跑但粗糙、不少网盘其实连不上」的状态，做到普通 Mac 用户拿来就能用、挑不出毛病的成品。
> 每一条都有编号（如 `UI-PANEL-07`），都要做，都要在 `docs/OPTIMIZATION-REPORT.md` 里逐条给出结果和证据。

## 2. 现状基线（2026-11-04）

- 测试：12 个包共 243 项，全部通过；包代码行覆盖率合计 69.9%；`App/`（3,722 行）和 DevTool 没有任何测试。
- 完全不能用的类型（审查已亲自核对）：Google Drive（`?fields=` 被编码进路径，请求 404）、Dropbox（读昵称必失败，改名移动永远失败）、OneDrive（中文和空格路径编码两次）、天翼（`https` 被改成 `httpss`）。
- 数据安全风险：ADB 覆盖文件中断会丢原文件、`mv` 语义错误；迅雷、移动云盘的删除可能是永久删除；令牌刷新遇到断网就永久作废登录（阿里、PikPak、天翼、OAuth 公共层）。
- 发布：没有自动更新、没有应用图标、没有资源目录（`Assets.xcassets`）、版本号写死 0.1.0、签名用 Apple Development 且不加时间戳。
- 截图审视发现的主要问题（证据在 `docs/screenshots/`）：
  - 面板空状态里同时出现两个「添加位置」按钮（中间主按钮 + 底部整条按钮）。
  - 类型选择页：窗口标题「添加位置」和页面大标题「添加位置」重复；图标风格混乱（有的实心彩色、有的黑色线条、有的蓝色、有的青色）；卡片很大，28 种类型要滚很久；「SMB 共享（Windows / Mac / NAS）」标题折成两行；说明文字和标题重复（「WebDAV / HTTP WebDAV」「相机（USB）/ 相机的 USB 连接」）；WebDAV 和 WebDAV over HTTPS 拆成了两张卡；搜索框里光标压在占位文字上。
  - 表单页：大标题又是「添加位置」；右上角孤零零的「连接设置」；「使用访客登录」夹在主机和用户名之间；密码的显示按钮跑到输入框外面；「列出共享」「测试并保存」禁用时看不出为什么禁用；字段是自己拼的「标签在上、输入框在下」，不是 macOS 表单的样子。
  - 设置：自己拼的单页，不是原生的分页设置；页面里又写了一遍大标题「设置」；开关用的是复选框；「缓存上限：5 GB」把数值拼进标签里，步进器在最右；「允许系统通知」按钮和说明挤在一行；标题栏白色、内容区灰色，有一道明显的接缝。
  - 只截过空状态面板，从未验收过有位置、连接中、出错、需要重新登录、已挂载时的面板。

## 3. 设计基准（所有界面通用）

### 3.1 布局与间距

- `DS-01` 所有间距、内边距、尺寸取 4 的倍数。窗口内容边距 20；相关控件之间 8；分组之间 20。
- `DS-02` 圆角递进：内圆角 = 外圆角 − 内边距，同一层级同一圆角，最小 4。所有自己画的圆角一律 `style: .continuous`。半径集中定义（如 `Radius.panelRow = 10`、`Radius.tile = 8`、`Radius.card = 12`），禁止散写数字。
- `DS-03` 对齐：同一列文字起点、同一表单控件右缘对齐；带图标的列表项，图标放在固定宽度列里。
- `DS-04` 尺寸由内容决定：设置分页、sheet 按内容定高，内容超过屏幕可用高度才滚动。不允许底部大片空白，不允许裁切。
- `DS-05` 普通窗口（添加 / 编辑、网页登录）可调整大小，有最小尺寸，记住上次位置和大小（审查第 3 节第 1 条：现在全部写死且不能调）。
- `DS-06` 窗口标题栏和内容区底色一致，不出现接缝（设置截图里的白灰两色）。

### 3.2 字体

- `DS-07` 只用 macOS 文本样式，不写死字号（审查第 3 节第 2 条列出的 9pt 等全部替换）。界面文字最小 10pt。
- `DS-08` 窗口里不重复窗口标题：窗口标题已经写了「添加位置」「设置」，页面内不再写同样的大标题。
- `DS-09` 层级 2–3 级；数字一律 `monospacedDigit()`（容量、版本号、配对码、端口）。
- `DS-10` 中英文排版：中英文、数字之间半角空格；中文全角标点；多行文字检查断行，不让单词拆两行，中文最后一行不只剩一两个字（调整文案或宽度）；中英文都要看。

### 3.3 颜色

- `DS-11` 新建 `App/Assets.xcassets`（XcodeGen 的 sources 加入），把 `KayoiTheme` 的颜色全部迁过去，每个色集给浅色、深色、增强对比度（浅、深）四个值。代码里不再写十六进制，不再写 `.black.opacity(…)`、`.white`、`.red`、`.orange`（审查第 3 节第 12 条）。
- `DS-12` 统一用户可选的 8 种位置颜色：编辑器色块、面板图标、表头图标用同一组色集，每种都有浅深两套值（审查第 3 节第 11 条：现在编辑器用系统色、面板用自定义 RGB，两边对不上）。
- `DS-13` 对比度：所有「文字 / 背景」组合在浅色、深色下 ≥ 4.5:1，小字 ≥ 7:1；增强对比度下边框、分隔线明显可见（审查第 3 节第 13 条：现在边框 0xDCE5E1 对 0xEDF2F0 几乎看不见）。新增 `ColorContrastTests` 覆盖每一个实际使用的组合，包括绿底按钮上的文字（`actionText`）、禁用按钮、错误红字、橙色提示。
- `DS-14` 主色绿只用在：主按钮、选中状态、已挂载状态、菜单栏圆点。卡片、行的底色和边框用中性色。
- `DS-15` 状态颜色永远和图标或文字一起出现。

### 3.4 控件与反馈

- `DS-16` 按钮：实色填充加细边框（AGENTS 规定），每个视图最多一个主按钮。`FlatButtonStyle` 补齐悬停（亮一级）、按下（暗一级 + 下移 1pt，120ms）、键盘焦点环（沿按钮圆角）、禁用（整体降低不透明度，文字仍可辨认）四种状态（审查第 3 节第 6 条）。
- `DS-17` 设置和表单里的开关用 `Toggle`（switch 样式），不用复选框；勾选框只用于列表里的多选。
- `DS-18` 自定义可交互区域（面板行、类型卡片、颜色色块、密码显示按钮、搜索清除按钮）都有悬停反馈、按下反馈、键盘焦点环、`.contentShape`；非按钮的可点击区域用手形指针（审查第 3 节第 5、7、9 条）。面板去掉 `.focusEffectDisabled()`，改为只在行上显示焦点。
- `DS-19` 每个只有图标的按钮都有 `.help()` 和无障碍标签，`.help` 末尾写快捷键。类型图标对 VoiceOver 隐藏，由行的完整标签代替（审查第 3 节第 10 条）。
- `DS-20` 状态图标成对：挂载 / 推出、显示 / 隐藏密码（`eye` / `eye.slash`）、通知开 / 关（`bell` / `bell.slash`）。

### 3.5 动效

- `DS-21` 动效只用于说明变化，120–350ms，`.snappy` 或轻微回弹的 spring。
- `DS-22` 多个元素同时出现时错开：第 n 个延迟 `24ms × n`，位移 `A × 0.7ⁿ`（新发现的设备出现、分组展开）。
- `DS-23` 系统「减弱动态效果」打开时，位移、缩放改为淡入淡出或直接切换；拖动排序只保留插入线。

### 3.6 浮层怎么选

- `DS-24` 只补充说明文字的用 `.help`；要放操作的用点击打开的 popover（例如错误的「详细信息」）。
- `DS-25` 能撤销的直接执行并给撤销（调整排序、改颜色、改名）；不可逆的才确认：删除位置用弹窗（写出名称和具体后果）；清空缓存、重新生成 ADB 密钥用就地确认或弹窗，按影响大小选。
- `DS-26` 短表单用 sheet，主要任务用独立窗口（添加 / 编辑位置、网页登录），只补充信息的用 popover。

## 4. 逐界面规格与验收

每个界面都在浅色、深色两种外观和中文、English 两种语言下验收（§14）。§3 默认全部适用。

### 4.1 菜单栏图标

- `UI-ICON-01` 四种状态，各在浅色、深色菜单栏截图：空闲；有已挂载的位置（4–6pt 圆点）；正在连接或测试（两帧交替，减弱动态效果时不动）；需要处理（有位置出错或需要重新登录，系统橙圆点）（审查第 3 节第 16 条：现在只有挂载 / 未挂载两种）。
- `UI-ICON-02` 圆点在深浅菜单栏都清晰，位置对齐像素网格；图标保持模板渲染，圆点自己着色。
- `UI-ICON-03` 无障碍标签随状态变化：「Kayoi，2 个位置已挂载」「Kayoi，1 个位置需要处理」。

### 4.2 菜单栏面板（宽 380，最高 560）

- `UI-PANEL-01` 标题区：左边「Kayoi」（`.title3`、`.bold`）；右边状态胶囊只在有意义时出现：「2 个已挂载」「1 个需要处理」「正在连接…」，点击胶囊滚动到对应的行。
- `UI-PANEL-02` 两个分组：「已发现」（只在有发现时出现）在上，「我的位置」在下；分组标题 `.caption`、`.secondary`、半粗。
- `UI-PANEL-03` 行（已保存）：高 52；左侧 28pt 类型图标（§8 自画，用户所选颜色）；名称（`.body`，1 行，末尾截断，完整名称放 `.help`）；副标题（`.caption`，状态，最多 2 行）；右侧主操作。悬停时整行 `.quaternary` 圆角底色，按下加深，键盘选中有焦点环。
- `UI-PANEL-04` 行的状态矩阵，每一种都要有预览和演示截图：

| 状态 | 副标题 | 右侧操作 |
|---|---|---|
| 未连接 | 「未连接」 | SMB / WebDAV / NFS：「挂载」；其他：「测试连接」 |
| 设备未插入 | 「手机未连接」「相机未连接」 | 「测试连接」禁用，`.help` 说明原因 |
| 连接中 | 「正在连接…」 | 小进度圈 + 取消按钮（`xmark`，`.help`「取消」）（审查第 3 节第 15 条） |
| 等待授权 | 「请在手机上点“允许 USB 调试”」 | 取消 |
| 测试成功 | ✓「已连接 · 可用 120 GB / 共 256 GB」；容量未知时只写「已连接」，不写「可用 0 字节」（审查 1A 第 6 条） | 「重新测试」 |
| 已挂载 | ●「已挂载 · 可用 120 GB」 | 「推出」；单击行的文字区域在 Finder 打开 |
| 推出中 | 「正在推出…」 | 进度圈 |
| 失败 | 红色「无法连接：用户名或密码错误」，最多 2 行 | 「重试」+ ⓘ 按钮，点开 popover 显示完整原因、建议、「复制详细信息」 |
| 需要重新登录 | 橙色「登录已过期」 | 「重新登录」 |

- `UI-PANEL-05` 已发现的行：和已保存行同样布局，图标用中性灰色版本，副标题写来源（「USB · Pixel 8」「局域网 · DESKTOP-PC」「Wi‑Fi 无线调试」），右侧「添加」按钮（`plus`）。已保存的设备不再出现在「已发现」；同一台设备只出现一次（GR IV 不再出现两次，审查 1B；无 host 的 SMB 主机不再被误过滤，审查 1A 第 4 条）。
- `UI-PANEL-06` 空状态：只有一个「添加位置」主按钮；插图用 §8 自画的「文件夹 + 链接」图标（64pt），下面一句说明「插上手机、打开无线调试，或添加网络共享和网盘」。**列表为空时不显示底部的「添加位置」整条按钮**；列表不为空时，底部的「添加位置」改为行样式的紧凑按钮（`plus` + 文字，`.secondary`），左对齐在行文字起点。
- `UI-PANEL-07` 发现出错的提示条：圆角 10，橙色 15% 底，一句原因 + 一个操作按钮。本地网络权限被拒 →「打开本地网络设置」；USB 和相机发现出错也要显示（审查第 3 节第 14 条）。按错误类型判断，不靠匹配文案（审查 1A 第 8 条）。

## 8. 自己画的图标（kubai-icons）

### 8.1 用在哪里

| 位置 | 内容 | 尺寸 |
|---|---|---|
| 每种位置类型 | 28 种类型各一个图标（WebDAV 合并后 27 个） | 面板 28pt、类型格子 40pt、表单表头 48pt |
| 面板空状态 | 文件夹 + 链接 | 64pt |
| 设置页签 | 继续用 SF Symbols（系统设置的惯例），不自画 | — |
| 菜单栏图标 | 继续用模板化的单色符号，不自画 | — |

### 8.2 每种类型画什么

原则：表意比好看重要；同一类别结构相似、靠主色和标记区分；**第三方服务一律画原创图形，不照抄商标，旁边始终显示服务名**。

- 设备：安卓手机（中性的手机造型，不用安卓机器人商标）；理光 GR IV（扁平小卡片机：镜头偏左、无品牌字样）；USB 相机（单反造型）。
- 局域网：SMB 共享（显示器 + 文件夹）；WebDAV（文件夹 + 地球）；NFS（机柜）。
- 网盘（官方与实验性）：统一的「云 + 文件夹」结构，每个服务用不同主色，加一个简短标记区分：数字型名称直接用数字（115、123），其他用中性的首字或字母标记（不模仿对方 logo 的字形和造型）。实验性网盘在类型格子上另加「实验性」文字徽标，不在图标里表达。
- 对象存储：统一的「储物桶」结构 + 不同主色 + 简短标记（S3、R2、OSS、COS、Kodo、MinIO、B2）。
- 是否改用官方商标，由用户提供素材并确认授权后再换，本轮不做。

### 8.3 用户可选颜色

kubai-icons 的所有颜色都从一个主色推导，正好对应 Kayoi「每个位置可选图标颜色」的功能：

- `ICON-01` 每个类型图标按 8 种可选颜色各导出一份（`node scripts/export.mjs --only <类型> --accent <色值>`），面板行、表单表头用用户所选颜色那份；类型格子用该类型的默认颜色；「已发现」的行用中性灰那份。
- `ICON-02` 导出用脚本完成（`scripts/export-icons.sh`），不手工逐个导出；SVG 放进 `App/Assets.xcassets` 的 imageset，勾选「Preserve Vector Data」；代码通过一个 `TypeIcon(kind:color:size:)` 视图统一取图。

### 8.4 怎么画

- `ICON-03` 在仓库 `design/icons/` 下复制 skill 的 `index.html`、`src/`、`scripts/`（保留版权声明，不复制 `PROMPT.md`、`SKILL.md`），在副本里画。
- `ICON-04` 每个图标都运行 `node scripts/check.mjs --only <名字> --with 文件夹,邮件,下载`，按 skill `PROMPT.md` 第 10 节清单检查到全部通过；**重点看 24px、28px 下的辨识度**，因为面板里就是 28pt。
- `ICON-05` 报告附一张全部类型图标（默认颜色）+ 某一个类型的 8 种颜色总览图，浅色、深色背景各一张。
- `ICON-06` 图标源文件和导出的 SVG 都提交。

### 8.5 应用图标

- `ICON-07` Kayoi 目前没有应用图标。在 `design/app-icon/` 里画 3 个方向的 SVG 草案（主题「通う」：Mac 和手机、相机、网盘之间来回往返），按 macOS 图标网格（1024 画布、圆角矩形主体、统一投影），在 16、32、128、512 像素下各看一遍，挑辨识度最好的一个做完整，记进 DECISIONS（其余草案留在目录里供用户替换）。导出全部尺寸到 `AppIcon.appiconset`，浅色、深色 Dock 和 Finder 里各截图。
