# M7 第二步进度

## 第 1 小步：存储迁移

配置、历史日志和传统钥匙串条目已接入 App Group 与共享钥匙串。迁移先复制，再逐字节读回核对，所有项目核对通过后才清理旧值；部分失败可重试，新旧值冲突时停止。完成标记避免重复迁移后覆盖新数据。ADB 使用传统 `com.seaony.Kayoi` 中的原钥匙，不生成新钥匙；spike 测试数据保留到第 8 步。

每个进程先探测共享目录和共享钥匙串是否都可写、可读回，不可用时继续传统存储且不迁移。CLI 通过兼容 App 执行原命令，共用对应存储；参数、输出和退出码保持不变。可行性参考 [Apple TN3137](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains) 和 [Apple 对命令行共享钥匙串的说明](https://developer.apple.com/forums/thread/836816)。

本机先正常退出旧 Debug，备份整个旧数据目录到 `build/backup-20261111-205438/`，3 个文件逐字节核对通过。真实迁移复制配置和 2 份历史日志，迁移 1 个传统钥匙串条目；运行日志记录全部读回核对通过。迁移后配置与备份逐字节一致，历史日志完整，旧配置与传统 ADB 条目已清理。共享配置有 1 个安卓 USB 连接，spike 验证文件和测试钥匙未动。

Core 测试覆盖成功、部分失败后恢复、重复运行、新旧数据冲突、共享钥匙串不可写、共享目录不可写，以及共享探测不触发迁移。CLI 测试覆盖两种存储、双语错误、兼容 App 定位及真实进程的参数、输出、退出码转交。具体门禁与实测结果见 [验收记录](ACCEPTANCE.md)。

发布流程未修改。本轮只用带描述文件的 Debug 验收；当前 Release 没有可用的共享钥匙串授权，运行时继续传统存储。旧位置和新位置不做同步，正式分发的签名、描述文件与扩展嵌入方式仍待单独决定。
