# M7 第二步进度

## 第 1 小步：存储迁移

配置、历史日志和传统钥匙串条目已接入 App Group 与共享钥匙串。迁移先复制，再逐字节读回核对，所有项目核对通过后才清理旧值；部分失败可重试，新旧值冲突时停止。完成标记避免重复迁移后覆盖新数据。ADB 使用传统 `com.seaony.Kayoi` 中的原钥匙，不生成新钥匙；spike 测试数据保留到第 8 步。

每个进程先探测共享目录和共享钥匙串是否都可写、可读回，不可用时继续传统存储且不迁移。CLI 通过兼容 App 执行原命令，共用对应存储；参数、输出和退出码保持不变。可行性参考 [Apple TN3137](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains) 和 [Apple 对命令行共享钥匙串的说明](https://developer.apple.com/forums/thread/836816)。

本机先正常退出旧 Debug，备份整个旧数据目录到 `build/backup-20261111-205438/`，3 个文件逐字节核对通过。真实迁移复制配置和 2 份历史日志，迁移 1 个传统钥匙串条目；运行日志记录全部读回核对通过。迁移后配置与备份逐字节一致，历史日志完整，旧配置与传统 ADB 条目已清理。共享配置有 1 个安卓 USB 连接，spike 验证文件和测试钥匙未动。

Core 测试覆盖成功、部分失败后恢复、重复运行、新旧数据冲突、共享钥匙串不可写、共享目录不可写，以及共享探测不触发迁移。CLI 测试覆盖两种存储、双语错误、兼容 App 定位及真实进程的参数、输出、退出码转交。具体门禁与实测结果见 [验收记录](ACCEPTANCE.md)。

发布流程未修改。本轮只用带描述文件的 Debug 验收；当前 Release 没有可用的共享钥匙串授权，运行时继续传统存储。旧位置和新位置不做同步，正式分发的签名、描述文件与扩展嵌入方式仍待单独决定。

第 1 小步提交后按用户决定做了一次手工兼容恢复：旧配置与备份逐字节一致，传统 `com.seaony.Kayoi / adb.private-key` 从共享值复制回登录钥匙串并读回核对，系统命令确认存在。新位置、备份及 spike 均未改动，临时工具未提交。恢复时实测发现默认 SecItem 查询会搜索到共享条目，传统存储已显式指定 `kSecUseDataProtectionKeychain=false`，其他三处共享查询均明确为 true。另补迁移失败后本次退回传统存储继续启动、下次重试；CLI 在迁移未完成时也使用旧位置。失败期间旧端继续编辑或刷新后，重试依据仅含名称与 SHA-256 的迁移记录更新本次留下的副本，未知差异仍停止。最终构建与完整测试通过，Core 153 项，全仓 919 项 Swift 测试和 14 项脚本测试。

## 第 2 小步：真实文件系统骨架

假数据卷已删除，扩展按 `kayoi-<类型>://<连接ID>` 从共享配置读取连接，默认只读共享钥匙串，创建对应 Provider。23 个 scheme 覆盖 24 种已有非系统连接类型，USB 与 Wi-Fi 共用 `kayoi-adb`；SMB、WebDAV、NFS 及本轮保留原行为的 GR 不经过此分发。扩展单独保留了网络、USB、IOKit 例外权限，并复用中英权限说明及开放平台配置占位。ADB 工厂现在显式传递同一身份到 USB、Wi-Fi TLS 与 ADB 握手。

通用后端按卷串行调用 Provider，目录缓存设备 5 秒、网盘 30 秒，写入和路径变化立即失效。支持 Range 的直接按范围读，不支持的下载到扩展容器，所有连接共用默认 5 GB 的 LRU；下载中的预留也计入配额。写入先暂存，关闭或同步时上传，失败返回错误并保留本地内容，日志记录连接、路径、操作和恢复文件。已有文件写回与编辑器临时文件替换都先确认新内容完整，再移除旧目标、改名。只读与断线分别返回 `EROFS`、`EIO`，明确登录失效返回 `EACCES`。

FSKit 适配器使用 macOS 26 的 Operations 接口，回调在节点锁外调用；目录不返回点项。节点使用 Provider 的实际操作路径，Google Drive 等已编码的路径段直接用于文件系统名称，不丢弃同名显示项。不能区分的重复操作路径明确返回 `EEXIST`，不崩溃或猜选。属性查询刷新远端状态，文件修改时间传给本地上传文件。只读但能删除的设备有相应目录权限，实际上传仍按能力拦截。

本步使用本地替身和真实 FSKit 对象验证缓存、上传失败、替换顺序、属性刷新及关闭回调；不等同于真实挂载与传输验收。第 3 步覆盖层尚未接入，因此本步未向真实卷做 Finder 拷贝，避免产生远端元数据。具体构建、测试和未测项见验收记录。

P2 记录：不支持 Range 且单文件超过默认读缓存上限时返回 `EFBIG`，可继续用原 CLI 读取；多扩展进程同时下载的严格配额协调、超大目录及特殊名称额外变体留待真实使用证据，不扩展测试矩阵。未知容量按 FSKit SDK 要求保留默认 0，第 7 步再验证 Finder 行为，不伪造可用空间。
