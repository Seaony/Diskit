## 1. 缺陷与疑似缺陷

### 1A. App 层（我亲自读的，21 条）

1. **`AppModel.swift:493-509` 带「重试」的提示框按钮错位。** 三个按钮依次是重试、关闭、复制详细信息。代码把第二个按钮（「关闭」）当成复制处理，真正的「复制详细信息」点了没反应。→ 改为按第三个按钮判断复制。
2. **自己在 Finder 里推出也会被报「位置意外断开」。** `ConnectionManager.swift:281-285` 只要原来是已挂载、现在不在挂载表里，就调用 `unexpectedDisconnect`，通知在 `AppModel.swift:44-50` 发出，不区分是不是用户主动推出。→ 收到 `didUnmountNotification` 的视为正常推出，只在异常消失时才通知。
3. **手机和相机断开时永远不会发通知（F19）。** `ConnectionManager.swift:368-370` 只在状态为 `.mounted` 时才通知，而第一阶段的设备只会进入 `.tested`。POLISH-REPORT 的 A5 F19 写的「意外断开已接入」与此不符。→ 设备类改为在已测试成功或连接中被拔出时通知。
4. **`PanelView.swift:121` 已发现的 SMB 主机过滤有误。** `device.host` 为 nil 时，`params["host"] == nil` 对所有没有 host 的已保存位置都成立，结果只要存有任意一个非 SMB 位置，正在解析地址的 SMB 主机就被隐藏。另外过滤不限类型，主机名和 IP 对不上时会重复出现。→ 只和 `.smb` 比较，host 为 nil 时不过滤。
5. **从「已发现」点「添加」，窗口却显示「编辑位置」，而且没有「上一步」。** 点添加时把一个未保存的新 Connection 赋给了 `model.editing`（`PanelView.swift:419`），编辑器据此判断成编辑模式（`ConnectionEditor.swift:197,322`、`DiskitApp.swift:74`）。→ 增加「是否已存在于 connections」的判断。
6. **容量未知时显示「测试成功 · 可用 0 字节」。** 蓝奏和通用相机的 unsupported 被替换成 0/0（`AppModel.swift:59-64`）；S3 本身固定返回 0/0（`S3Provider.swift:148-153` ✔）；面板直接显示（`PanelView.swift:701-704`）。→ 容量改成可选值，未知时不显示。
7. **退出时用 `toggle` 推出卷**（`DiskitApp.swift:21-23`）。`toggle` 不是幂等的，期间状态一变就可能反向变成挂载。→ 提供明确的 eject 接口。
8. **`PanelView.swift:371` 靠判断提示文案里有没有「本地网络权限」来决定显示哪个按钮**，换语言或改文案就失效。→ 改用错误类型判断。
9. **拖动排序只能拖到某一行之前，拖不到最后一位**（`PanelView.swift:184,619-626`、`ConnectionManager.swift:158-167`）。→ 在列表末尾增加放置区。
10. **拖动时的半透明状态靠 sleep 1 秒复位**（`PanelView.swift:605-617`）。拖久了行会提前恢复，取消拖动可能残留。→ 在拖动结束或放置时复位。
11. **蓝奏编辑时清空分享密码，会在测试之前就删掉钥匙串**（`ConnectionEditor.swift:1359-1361`），测试失败后旧密码已经没了。→ 改到保存成功后再删。
12. **OAuth、PikPak、天翼类型出任何错（包括超时）都只给「重新登录」按钮**，并强制重新授权（`ConnectionEditor.swift:303-315`）。→ 只在鉴权错误时显示重新登录。
13. **「切换账号」可能切不了（需人工验证）。** `WebAuthorization.swift:31-51` 没设 `prefersEphemeralWebBrowserSession`；Google 没带 `select_account`，Microsoft 没带 `prompt`。浏览器会话保留着，很可能静默回到原账号（入口在 `ConnectionEditor.swift:809`）。→ 切换账号时用临时会话，或加 `prompt=select_account`。
14. **授权窗口锚点取自 `NSApplication.shared.keyWindow`**（`ConnectionEditor.swift:1240,1271`）。Diskit 不在前台时会抛出 `OAuthCallbackError.invalid`，错误信息误导人。→ 改用编辑器所在的窗口。
15. **几处同步文件读写跑在主线程上**：`AppModel.swift:374-458` 的 `writeError`、`cacheSize`、`enforceCacheLimit`，以及 `SettingsView.swift:134-144` 在 onAppear 里同步遍历缓存。→ 移到后台。
16. **日志文件按 UTC 日期命名**（`AppModel.swift:378-381`）。北京时间 0–8 点的日志会写进前一天的文件。→ 用本地时区。
17. **面板关闭后可能还在每 30 秒轮询（需人工验证）。** 轮询绑在 MenuBarExtra 内容上（`PanelView.swift:237-242`）；`.window` 样式的内容关闭后不一定销毁，那样就违反 PLAN §5「面板关闭停止轮询」。onAppear 里的选中和焦点设置也可能只在首次生效。→ 用面板可见状态控制轮询。
18. **可用空间可能不刷新（需人工验证）。** `SMB.swift:186` 用 `getmntinfo(MNT_NOWAIT)` 拿的是缓存值，30 秒刷新后显示的可能还是旧数。→ 改为对单个挂载点调用 `statfs`。
19. **扫码登录页的错误没有转成人话**（`QuarkLoginView.swift:75` 直接用 `localizedDescription`）。→ 改用 `HumanError.detail`。
20. **所有 `*_CLIENT_SECRET` 都打进了 Info.plist**（`project.yml` 的 info.properties、`AppModel.swift:145-229`），任何人都能从 .app 里读出来。OneDrive、Google、Dropbox 已经用 PKCE，却仍然发送 secret（`OAuthSession.swift:165-167,251-255`）。Google 不接受 `diskit://` 回调，`auth/drive` 是受限权限、需要审核（需人工验证）。→ PKCE 平台不再带 secret；Google 改用桌面或 loopback 回调。
21. **注册了 `diskit://` scheme，但整个 App 没有 `onOpenURL` 或 `handlesExternalEvents`。** 授权回调由 ASWebAuthenticationSession 自己接住，不受影响；但外部打开 diskit 链接时行为没有定义。低优先级。

### 1B. Core / ADB / 相机（子审计，44 条，按优先级）

**严重**
- **ADB 一次普通错误就让会话报废，而且重连不了**（`ADBSync.swift:140-143,179-182,254-257,308-311`、`USBTransport.swift:144-149`）。stat 一个不存在的路径，连接就废了。→ 只在传输或协议错误时断开；重连时重建传输层。
- **ADB 覆盖已有文件时直接 SEND 到目标路径，中断会丢原文件**（`ADBSync.swift:214-258`，需真机）。→ 先传到临时名，再 `mv`。
- **ADB 的 `mv` 语义不对**（`ADBSync.swift:265-267`）：目标是已有目录时会移进去，是已有文件时会静默覆盖。
- **编辑已挂载的系统挂载、改了地址后，旧卷成了孤儿，还会发一条假的「意外断开」通知**（`ConnectionManager.swift:127-151`）。
- **删除位置时先删钥匙串，后保存配置**（`ConnectionManager.swift:189-209`），保存失败时凭据已经丢了。
- **GR IV 在「已发现」里出现两次**：通用相机发现没有排除理光（`CameraUSBDiscovery.swift:37-51`）。

**中**
- 回滚失败会盖掉原始错误（`ConnectionManager.swift:111-117,137-145`）。
- `detailedErrors` 从不清空，过期错误一直显示（`:31,402-404`）。
- 挂载超时后迟到的成功会留下孤儿挂载（`SMB.swift:234-256`）。
- 挂载表匹配没做解码、NFC 规范化和大小写统一（`SMB.swift:95-100`，需人工验证）。
- 自动挂载不重试，循环里用的是旧快照（`ConnectionManager.swift:360-366`）。
- 403、EACCES 一律当成「需要重新登录」（`:389-399`）。
- 安卓 Wi‑Fi 连接实际走 USB 时被误判为断开（`:299-303`）。
- SMB 发现失败后不会恢复（`SMBDiscovery.swift:29-31,61-63`）。
- 共享列表可能被截断（`SMBProcess.c:70-71`）。
- HTTP 流每个字节 await 一次，CPU 开销大（`HTTPTransport.swift:116-122`）。
- stat v2 把 Linux errno 原样当 Darwin errno 用（`ADBSync.swift:28`）。
- 目录里一个 stat 失败或非 UTF‑8 的名字，整个目录列不出来（`:165-169`）。
- 上传后修改时间变成「现在」（`:246`）。
- `/sdcard`、`/storage`、`/SD 卡` 路径映射有歧义（`:117-128`）。
- 并发操作直接报 EBUSY，不排队（`:112-116`）。
- USB 用同步阻塞 IO，不响应取消（`USBTransport.swift:120-139`）。
- v1 协议下大于 4 GB 的文件大小静默截断（`ADBSync.swift:40-42,189-190`）。
- 等待手机授权超时后，提示的是「连接超时」而不是「请在手机上允许」（`ADBSession.swift:58-64`）。
- 每 64 KB 发一次 WRTE 并等 OKAY，可能达不到 M2-5 的 20 MB/s（`ADBSync.swift:234-243`）。
- 通用相机的能否删除在打开会话前就算死了（`CameraUSBProvider.swift:12-14`）。
- 通用相机永远拿不到容量（`ImageCaptureAccess.swift:123`）。
- 没有序列号的相机完全用不了（`CameraUSBDiscovery.swift:151`、`CameraUSBProvider.swift:20`）。
- 一个异常条目就让整台相机不可用（`ImageCaptureAccess.swift:118,227-235`、`RicohProvider.swift:117`）。

**低**
- 可用空间用了 Used 列，把保留块也算成可用（`:272`）。
- shell 退出包长度为 0 时一直等到超时（`:295`）。
- 没有 NFC 规范化。
- `hostName` 可能阻塞；首次生成密钥有竞态（`ADBIdentity.swift:16-25,58`）。
- USBDiscovery 用 `passUnretained` 注册，没有 deinit 解除（`USBDiscovery.swift:28-41`）。
- 端口被拒时白等 15 秒（`NetworkTransport.swift:108-121`）。
- TLS 接受任意设备证书（`:87-88`，与 AOSP 一致）。
- 序列号重复的手机无法区分（`USBTransport.swift:42`）。
- 内容目录只等 15 秒（`ImageCaptureAccess.swift:80-84`）。
- 理光每次操作都重建整棵目录树（`RicohProvider.swift:91-101`）。
- 理光错误映射不准（`ImageCaptureAdapter.swift:150-175`）。
- 断开后无法重连（`ImageCaptureAccess.swift:107`）。

### 1D. 阿里 / 夸克 / PikPak / 蓝奏（子审计，28 条）

**严重**
- **阿里刷新令牌遇到任何错误（断网、429、5xx）都会永久作废登录**（`AliyunOAuth.swift:248-258,299-301`）；PikPak 也一样（`PikPakSession.swift:226-257`）。
- **蓝奏的文件大小来自四舍五入的文字**，范围读取几乎都失败，Finder 显示的大小也不对（`LanzouValue.swift:66-83`、`LanzouProvider.swift:75-78`、`LanzouSession.swift:239-241`）。
- 蓝奏单文件分享页取的是页面里第一个「数字+单位」当大小（`LanzouSharePage.swift:57`）。

**中**
- 每个 provider 新建一个会话，合并刷新和 4 并发上限只在单个会话内有效（`AppModel.swift:153-157,258,284`）。
- 列目录期间重入，路径缓存会被旧数据回填（阿里、夸克、PikPak、蓝奏的 `children()`）。
- 蓝奏全量下载不检查响应，可能把 HTML 验证页当文件内容存下来（`LanzouSession.swift:224-227`）。
- 带密码的文件夹分享被判成单个文件（`LanzouSharePage.swift:26-32`）。
- 蓝奏 JS 抓取容易被诱饵代码骗过。
- 每次范围读取都把取链接的流程完整走一遍，拖动视频进度时请求成倍放大。
- 夸克、PikPak 在 provider actor 上同步算整文件哈希，期间其他操作卡住。
- 夸克、PikPak 跨目录改名时，目标目录已有原名会失败。
- 夸克删除和移动没有等异步任务完成。

**低（14 条）**：夸克 format_type 取了临时文件的扩展名；PikPak 自定义根目录逻辑错；PikPak 上传端点写死；PikPak captcha 缓存只增不清；captcha 错误被误报成密码错误；AliyunError 不在 POSIX 域；阿里 4 个并发名额会被没读完的下载流占住；mkdir 已存在时静默成功；夸克一次登录失效就删 Cookie；蓝奏 Cookie 解析失败被吞，刷新后的 Cookie 不持久；蓝奏相对时间按解析时刻计算，每次列目录时间都变；夸克空页直接报协议错误；每次新建 DateFormatter；PikPak 0 字节上传可能空等 300 秒。

### 1E. 天翼 / 移动 / 迅雷 / DevTool（子审计，26 条）

**严重**
- **天翼把 `https` 链接改成了 `httpss` ✔**，所有 https 下载链接都读不了（`TianyiProvider.swift:92`）。
- **迅雷删除调的是 `files:batchDelete` ✔**，很可能是永久删除，不进回收站（`XunleiProvider.swift:502-505`，需人工验证）。
- 移动云盘删除可能也是永久删除（`MobileCloudProvider.swift:358-359`）。
- 天翼网络抖动就删掉登录信息（`TianyiSession.swift:421-425`）。

**中**
- 天翼 Cookie 绑定的域名和跳转链可能拿不到会话（`TianyiSession.swift:34-49,330-347`，需人工验证）。
- 天翼文件名里的 `+` 没编码（`TianyiProvider.swift:190,246,256`）。
- 天翼分页可能静默截断（`:342`）。
- 天翼和移动的跨目录改名误报「已存在」。
- 迅雷上传进度的总量传错（`XunleiUpload.swift:127-129`）。
- 刷新没有合并，网络错误被当成登录失效。
- 迅雷和移动没有把网络错误映射成 POSIX。
- 风控、验证码被当成登录过期。

**低**：迅雷空的 `error` 字段也被当成错误；失败后缓存没清；移动 `exist` 时可能误删用户已有文件；移动容量单位存疑；14 位日期被当成时间戳解析；天翼登录在验证之前就写钥匙串；一个坏条目让整个目录失败；迅雷分片整块读进内存，最大可达 5 GiB。
